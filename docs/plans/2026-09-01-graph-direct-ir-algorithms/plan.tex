\section{Scope and goal}
The standard HyMeKo graph path must traverse the canonical \texttt{hymeko\_core::ir::Ir} sparse
signed-incidence \emph{in place}, via the borrowed \texttt{IncidenceIndex<'ir>} promoted to core
\texttt{main} (70b4f36) this session. No dense view, no \texttt{Ir$\to$SignedGraph} adapter, no
pairwise flattening, no materialized star/clique, no second hypergraph model, no new adapter crate.

\paragraph{Non-duplication (Phase 1 finding).} Hotaru already owns a mature general hypergraph suite,
and Nagare a dormant Berge/Levi traversal --- but both first \emph{copy} the Ir into a private CSR
model. The non-overlapping primitive we add is \textbf{zero-copy traversal of the canonical Ir},
at the correct layer (upstream of Nagare, parallel to Hotaru). Hotaru and Nagare are write-frozen
this session; overlaps are recorded as migration items R1--R3.

\section{Interface (public, canonical IDs only)}
\begin{itemize}[nosep]
  \item \texttt{TraversalWorkspace} --- caller-owned scratch: node-generation marks, arc-generation
        marks, frontier queue, predecessor node, predecessor arc, reusable result buffer. Generation
        counters with correct wrap handling. Warm reuse $\Rightarrow$ zero heap allocation.
  \item \texttt{HyperTraversal<'ir>} --- one structured facade borrowing \texttt{\&IncidenceIndex<'ir>}
        (which already borrows the Ir). No separate \texttt{\&Ir + \&IncidenceIndex} pairing. No
        builder/factory/alias trio for one operation.
  \item Required algorithms: \texttt{reachable\_nodes}, \texttt{berge\_shortest\_path},
        \texttt{connected\_components}, \texttt{dual\_reachability}.
  \item Optional (after the required layer is green): bounded Berge path / cycle enumeration,
        \texttt{s\_connected\_components}, batch reachability, Rayon batch with thread-local workspaces.
  \item Outputs: \texttt{NodeId}/\texttt{HyperArcId}/\texttt{DeclId}; Berge steps preserve node, hyperarc,
        ref-slot, sign, and weight/annotation accessibility. No context-free dense \texttt{u32} leaks.
\end{itemize}

\section{Complexity contract}
Target $O(\text{nodes}+\text{arcs}+\text{incidences})$ over the visited component. \textbf{Both}
\texttt{visited\_nodes} and \texttt{visited\_arcs} are mandatory: a $k$-member hyperarc is expanded at
most once per search, else the same arc is re-expanded from each of its $k$ members and the walk
degrades to $O(k^2)$. Topology rule: $+,-,\sim$ all connect; weight does not gate reachability;
duplicate incidence does not create a second visited node but multiplicity stays observable; a
self-incidence terminates.

\section{Test strategy}
Source-first: \texttt{*.hymeko $\to$ RealParser $\to$ ModuleStore::compile $\to$ Ir $\to$ IncidenceIndex $\to$
algorithm $\to$ canonical result}. Golden shapes (multiway, $+/-/\sim$, weights, duplicate, self-incidence,
many arcs per edge, shared node, empty/singleton, ragged arity, import/namespace, multi-component, Berge
path/cycle). Generated families (Steiner, sunflower, Mycielski, random-uniform, degree-skew, hub,
VLAN/failure-domain, service-dependency, humanoid, hexapod, chicken/biomedical). Independent $O(V\cdot E)$
oracle (not the production index, not the same generator). Metamorphic (DeclId permutation, insertion
history, import alias, duplicate incidence, slot order, disjoint union, non-semantic renaming). Fault
mutants, each caught by a named test (drop arc-visited; double-expand an arc; wrong predecessor arc;
sign/slot shift; dedup a duplicate; generation-wrap bug; queue-head reset bug).

\section{Performance budget}
Warm query: zero allocation. Direct traversal linear in visited incidences; no per-hyperedge $k^2$.
High-arity direct end-to-end faster than the clique control; within 3\% of the true sparse-star control
or profiled and explained. Serial deterministic; Rayon semantically identical. Peak RSS $<$16\,GiB.
Sizes: $\geq 10^5$ and $\geq 10^6$ incidences; high-arity; hub-skew; many tiny hyperedges; few very large.

\section{Risk anticipation}
Worst case: $10^6$-incidence hub-skew (one node in $10^5$ arcs) and a high-arity ($k=20$) instance ---
the inputs where a missing \texttt{visited\_arcs} silently reintroduces $k^2$ work. The benchmark's
falsifier watches exactly this: if adding arc-visited does not remove the high-arity blow-up, find the
residual multi-expansion; do not explain it as noise. Contract preservation: bounded enumeration MUST
carry \texttt{max\_depth}, \texttt{max\_results}, and a frontier/expansion budget with deterministic
termination --- no implicit unbounded all-path enumeration.

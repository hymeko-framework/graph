\section{Generator safety (D)}
Per family: compute vertex/unit/arc/incidence counts, estimated source bytes and
max edge cardinality by \emph{checked} arithmetic \emph{before} allocating any
large \texttt{Vec}/\texttt{String}; wrap $\to$ typed \texttt{ArithmeticOverflow};
over cap $\to$ typed \texttt{TooLarge}. \texttt{usize::MAX}-adjacent params never
allocate; negative tests never panic/OOM. Source emission is $O(\text{output})$
with \texttt{write!}. \texttt{SOURCE\_CAP\_BYTES} documented; a test proves the
guard fires before allocation. No blanket \texttt{\#![allow(dead\_code)]}: scope
to item-level where a helper is used by a subset of test binaries.

\section{Independent oracle (E)}
Each family computes \texttt{ExpectedStructure} from \emph{parameters} by formula,
separately from the built edge list; the edge-derived counts are then cross-checked
against it (catches common-mode). One tiny per family is a hand-checked golden.

\section{Scale contract (L, option B)}
Families carry explicit parameters; \texttt{WorkloadScale} is a label
\emph{computed} from the incidence count: tiny $<10^2$, small $10^2$--$10^3$,
medium $10^4$--$10^5$, large $10^5$--$10^6$, stress $>10^6$. Prior ``large'' cases
renamed honestly. Default tests: every family tiny + $\ge1$ small; one medium per
category where affordable. Ignored: $\ge1$ math/random large + one network/robot
large + a stress \texttt{\#[ignore]}, each with a documented command; the required
large cases are actually run this phase.

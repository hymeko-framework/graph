\section{Risk anticipation}

\begin{itemize}
\item \textbf{Unrelated dependency drift.} In the sibling network pin, the targeted
\texttt{--precise} update also moved \texttt{parser}. Mitigation: audit the
lockfile diff line by line; pin \texttt{parser} (and anything else) back to its
baseline revision; if the \texttt{hymeko\_core} change cannot be isolated, halt
without committing.
\item \textbf{Two \texttt{hymeko\_core} versions.} \texttt{cargo tree -d} before and
after; a second copy is a rejection.
\item \textbf{Host resolution.} \texttt{amaterasu.local} may not resolve; use a
per-command URL rewrite to \texttt{192.168.1.228:2222} with
\texttt{HostKeyAlias=[amaterasu.local]:2222}, never a config edit.
\item \textbf{Worst-case input.} The committed P-graph fixtures under \texttt{data/}
are the production-scale inputs for the oracle.
\end{itemize}

\section{The audit (read-only, deliverable of this phase)}

A full \texttt{rg} sweep over \texttt{decl\_nodes}, \texttt{.nodes}/\texttt{.edges}/%
\texttt{.arcs}, \texttt{decl\_to\_*}, \texttt{.0}, \texttt{raw()} and
\texttt{Id::new} in \texttt{hymeko\_pgraph} \texttt{src/}. Every \texttt{.0} is
classified individually (many are not IR ids). Each real site gets: file:line,
current contract, strict/tolerant, needed accessor, error model, mapping-only vs
checked-composite, iteration-order requirement, hot-path class, needed test,
migration risk. The old ``7 site'' estimate is not treated as truth; the actual
inventory is the next phase's scope. New core accessors, if any are needed, are
\emph{documented, not implemented}.
